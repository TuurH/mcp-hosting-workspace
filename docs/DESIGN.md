# Current design

This document describes the implemented system. [SETUP](SETUP.md) describes installation, [OWNER-GUIDE](OWNER-GUIDE.md) describes workflows, and [APPLICATIONS](APPLICATIONS.md) / [APP-CAPABILITIES](APP-CAPABILITIES.md) define application controls.

## Trust boundaries

| Component | Responsibility | Important boundary |
| --- | --- | --- |
| Workspace | AI shell, jobs, persistent files, CUDA tools | Sudo and configured internet/LAN access; no Docker socket |
| Files service | Snapshot/stream expiring exported downloads | Workspace mounted read-only; separate public and private minting interfaces |
| Admin | Owner forms, credentials and file management | Owner Access verification, CSRF/origin checks; full deployer API through a Unix socket |
| Deployer | State, reviewed app operations, routing, resource/GPU policy | Trusted Docker socket holder; narrow AI API on a separate internal network |
| Pomerium | Visitor Google login, application audience, WebSockets | Routes are generated by the deployer; raw listeners do not use it |
| Caddy | Static app files and visitor logs | Internal upstream; no public host port |
| cloudflared | HTTPS tunnel | Dedicated edge networks and trusted forwarding IPs |
| Managed app | Reviewed components and private persistent data | Immutable revision, bounded resources and owner-granted capabilities |
| Build/development helpers | Build candidate images or mutate a separate development layer | No live data, credentials, workspace tokens or Docker socket |

The Compose infrastructure is reached through the tunnel, without host ports. The local override intentionally changes that for diagnostics. App raw TCP/UDP listeners are a separate owner-authorized exposure. Platform/internal Docker destinations remain excluded from application network grants, including LAN exceptions. Direct outbound IPv6 remains denied.

## Independent app controls

Visibility answers who can open the website: **Only you**, **Shared**, **Public**. An environment label records development/staging/production intent; it grants no permission and creates no additional deployment. Each app has one live revision, an optional isolated preview and, for runtimes, an optional mutable development session.

Production protection supplies default approval behavior. Explicit AI permissions separately control package development, platform web tests, lifecycle changes, bounded automatic deployment and deletion. General shell commands in an approved development session can inherently test code/install packages; the web-test permission does not restrict shell semantics.

Source submission binds a normalized manifest to exact source/image identity. Runtime work has persisted operation states: queued, running, succeeded, failed or interrupted. Image build completion is separate from release. The owner page lists build, capability and credential prerequisites; backend checks remain authoritative. Preview readiness is not production acceptance: previews have empty separate data and no credentials, outbound network, GPU, listeners or background components.

Release serializes background components and may briefly interrupt service. Code rollback retains data. Tasks have persisted start records; schedules run at fixed intervals of at least 60 seconds without overlap. Interrupted tasks need explicit review/new revision. Recovery reconciles declared live components after firewall checks and prevents pending/preview components becoming production by accident. Offline intent is retained.

## Credentials and data

App values and workspace token values are encrypted in platform state. Values are entered by the owner and omitted from management responses/audit records. App credential grants bind names to an exact revision. Workspace tokens enter new workspace processes and never app containers. Code that receives a value can read it; this is not protection from granted code. Rotation needs an app restart or stopping old workspace jobs to discard their old copy.

Each app's `/data` is private and shared only by opted-in components. Deleting an app retains its data. Approved exports copy selected paths into a unique workspace inbox directory, with byte/file bounds and SHA256 provenance, after stopping the app. The copy is readable by the workspace AI. Exports do not create continuing volume access.

Mutable development is isolated from production and reset by grant replacement. Package commands record bounded output, inventory observations/errors and dependency changes. Snapshot freezes installed layers and source into a release candidate; ordinary backups do not capture unsnapshotted mutable layers. Build inventories are observations, not an attestation of every opaque installer.

## Resource and availability limits

CPU and memory limits apply per component; a multi-component app can use their sum. Storage is measured/budgeted on Docker's shared disk, not a hard volume quota. GPU devices are shared, with no VRAM allocation guarantee. Rootless build caches also share disk capacity. Bounded scans/logs/inventories explicitly report truncation or partial results.

Gaming lowers CPU/memory policy and holds approved GPU apps/development. The workspace GPU flag is cooperative because its shell has sudo; outside-workspace enforcement checks/kills GPU work and may hold/freeze the workspace when verification fails. Frozen processes can retain VRAM. True device removal requires workspace recreation without the GPU reservation. GPU process UI covers the main workspace; it is not a whole-host process inventory.

Routing status reports requested/applied configuration and anonymous checks, not proof of every signed-in audience. Removing a person affects subsequent HTTP requests; established WebSockets can remain open. Take a runtime app offline to close its connections. The emergency access lock overrides website visibility and stops raw-listener apps/development, preserving saved visibility and protection; restore access and explicitly start stopped development sessions afterwards.

The host must stay awake, signed in and online. There is no host redundancy. Backups save labelled volumes, selected workspace folders and retained immutable images; `.env` is protected separately. Copying live database files is not automatically consistent. Restore verifies archives, stops infrastructure/managed helpers and leaves the stack stopped on failure. See the restore drill in GO-LIVE.

## Validation boundaries

Unit tests cover API validation, authentication, grants, state transitions and recovery logic. CI adds real Docker isolation/network/component checks, PowerShell parsing and populated browser layouts. Installed-host acceptance additionally checks real Google audiences, Cloudflare OAuth/cache/routing, Windows raw-port forwarding, NVIDIA compatibility, gaming and restoration. Passing one layer does not certify the others.
